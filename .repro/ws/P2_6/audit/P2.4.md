  `texts = new Set(d.items.map(i=>i[0]))`, and an order drill's items are strings, so `i[0]` is the first character.

### F9: read credit starts from the topic's own scroll position

**Defect 1. A topic reached from the bottom of another one got the old scroll credit.**
- *What the verifier saw.* rp8 recorded `scrolled` 0.934 while it sat at scrollY 0, and it was marked read without
  ever being scrolled.
- *Cause.* `go()` calls `render()` before `window.scrollTo(0)`. `render()` calls `wire()`, which calls `wireGrid()`,
  which calls `startDwell()`. `startDwell()` read `window.scrollY` straight away, and that was still the previous
  topic's position.
- *Fix.*
  - A topic that is not already being tracked starts at `dwellSeconds = 0` and `maxScrolled = 0`.
  - The first reading waits two animation frames, so `go()`'s scroll to the top and `restoreScroll()` have both run.
    After that, only real scroll events move `maxScrolled`.
  - Every way to switch topics goes through `go()`, then `render()`, then `startDwell()`: the rail, the next and
    previous buttons, search, and the `[data-t]` and `[data-gototopic]` links. So all of them are covered.
  - Only the same topic re-rendered in place (a sexp answer, the cloze toggle, a grid retake) keeps its running
    counters.
  - The interval now sets `dwellTimer = null` when it stops, so "same topic" means it is still being tracked.

**Defect 2. After the recall grid was scored, the chip still said "reading 8%".**
- *Cause.* The grid handler set `rec.read = true` but never touched `#dwellTag`. The dwell tick only painted the chip
  while `!rec.read`.
- *Fix.* `paintDwellTag(t)` paints the chip from the topic's record:
  - "read" in the good color when `rec.read`;
  - otherwise "reading N% · scrolled M%".

  It is called by the dwell tick, by the grid check handler and when `startDwell` runs. So a same-topic re-render no
  longer flashes "not read yet".

The read rule is unchanged: at least max(45 s, 0.35 × mins × 60) of visible dwell and at least 70 % scrolled, or a
scored grid.

### K13: the multi drill collapses to one column below 760 px

- *Cause.* The end-screen `.disc` and the running board's `.sortbtns` had an inline
  `grid-template-columns:repeat(3,1fr)`. No media query can override an inline style.
- *Fix.*
  - Both elements now carry `class="... dmulti" style="--dcols:N"`, where N = min(3, number of columns).
  - The shell has `.disc.dmulti,.sortbtns.dmulti{grid-template-columns:repeat(var(--dcols,3),minmax(0,1fr))}`.
  - `@media (max-width:760px){... minmax(0,1fr)}` makes it one column.
- *Sort end screen.* It already collapsed through `.disc`'s auto-fit, and it is unchanged.

## Image-set fix

Reopened 2026-09-28 for one defect that the last P2.3 redo found in F20 (image spot sets). The finding, verbatim: "The
Images view's startSpot('unseen') still fills with every image when none are unseen."

**Cause.** `startSpot` filtered to images with no `S.spot` record, then ran `if(!keys.length) keys = Object.keys(IMGS)`.
So once every image had been tried, "Only ones I have not seen" and the plan's image row served the whole set under
that label. The two Images buttons showed no count ("Start — N images" counted every image; "Only ones I have not
seen" had none), and the plan row counted without "High yield only", which the builder beside the buttons already
applied.

**Fix.** The P2.3 pattern (audit/P2.3.md §5): one pool function per set, every count taken from that pool, and an
honest empty-set notice instead of a random fill.

**Files changed:** `engine/engine.js` and `engine/ENGINE-GLOBALS.md` (the `IMGS` row names `spotPool`).
`engine/base/`, `engine/extract_engine.py`, `engine/shell.html` and `engine/selftest.js` are untouched.

### The rule for each image set

`S.spot[key]` = `{ok, n, ts}` is written by the first answer to an image, right or wrong, and rewritten by every later
answer. So `ok` is the result of the most recent answer. Images have no spacing schedule: the record has no box and no
due date.

| Source (label) | Rule | Count shown |
|---|---|---|
| Images view: **All images, shuffled (n)** (`data-sp="all"`; was "Start — N images") | `spotPool("all")`: every image. Shuffled, no cap | `setCount("spot","all")` |
| Images view: **Not tried yet (n)** (`data-sp="unseen"`; was "Only ones I have not seen", no count) | `spotPool("unseen")`: images with no answer yet. Shuffled, no cap. **No fallback:** an empty set shows the notice | `setCount("spot","unseen")` |
| Plan: "N images you have not tried yet" (`sp:unseen`) | opens `startSpot("unseen")`, the set above | the same `setCount`. The row goes when the set is empty |
| Builder, status **Not tried yet** (was "Never identified") / Got wrong / Got right | no record / the most recent answer was wrong / right (`bldMatch`, unchanged) | "Start N images" = `bldOrdered`, unchanged |
| Builder, topic chips (per-topic images) | the image's teaching topic (`IMGTOPIC`, the topic whose body places it) | same |
| Search result (an image) | that one image | — |

- **"High yield only"** now filters the two named sets and the plan row the same way. It keeps the images whose
  `IMGTOPIC` is high yield on the chosen axis, which is what the builder already did. The label says so ("All
  high-yield images, shuffled", "N high-yield images you have not tried yet"). The header banner now reads
  "every question, rapid pick and image is drawn from them".
- **"Never identified" was renamed** because the rule is "no answer yet". An image tried and missed has never been
  identified, yet the status did not serve it.
- **Missed or due images.** There is no named "missed" or "due" image set to fix. Missed images are the builder's
  "Got wrong" status, checked below. Images carry no due date, and the builder offers no "Due" status for them.

**An empty set says so.** `startSpot` sets `SET_EMPTY = {m:"spot", k}` and shows the Images index with the P2.3
`.call.step.setempty` notice at the top (`setEmptyHTML`, extended for `m === "spot"`). The notice:
- is marked `data-verdict`, so `#live` announces it;
- names the set and why it is empty. For example: "You have tried every image. An image leaves this set with your first
  answer to it, right or wrong. To go back over the ones you got wrong, open 'Build your own set' below and choose 'Got
  wrong'." When "High yield only" is what emptied the set, it says that instead;
- offers the other non-empty image set by name and count (at most two exist): "Try instead: All images, shuffled (2)";
- clears on the next navigation, on the next set that starts, and now also when search opens an image. Without that,
  finishing a searched image left the previous notice showing on the index.

**Label of a running set.** The toolbar now names the set: "Not tried yet · Image 1 of 2", "All images, shuffled · …",
"Your own set · …", "From search · …". The name is stored in `S.sp.name` when the set starts, so toggling the yield
filter mid-set does not rename a set already served.
